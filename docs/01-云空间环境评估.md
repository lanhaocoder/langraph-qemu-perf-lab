# LanGraph 云空间运行环境评估

## 环境

| 项目 | 值 |
|---|---|
| 内核 | `6.6.117-45.19.1.tl4.x86_64` |
| 架构 | x86_64（云沙箱，非 arm64 目标板） |
| `perf_event_paranoid` | 2 |
| `CapEff` | `0x1ffffffffff`（表面全能力，但受 seccomp 约束） |
| cgroup | `0::/init.scope`（容器化隔离） |

## 实测结果

| 能力 | 结果 | 证据 |
|---|---|---|
| perf 工具 | 已安装 6.8.0-149 | 与运行内核版本不匹配，wrapper 拒绝启动 |
| `perf_event_open` 系统调用 | **失败** | 直接 syscall 返回 `EPERM` |
| 软件事件 `task-clock` | **失败** | `No permission to enable task-clock event` |
| 硬件事件 `cycles` | **失败** | `No permission to enable cycles event` |
| tracepoint `sched:sched_switch` | **失败** | `Unable to find debugfs/tracefs` |
| 挂载 tracefs / debugfs | **拒绝** | `permission denied` |
| `/sys/kernel/tracing` | 空目录 | 无 `available_tracers`、`trace` 等文件 |
| trace-cmd | 已装 3.2.0 | 采集不可用（无 tracefs），解析库可用 |
| LanGraph 编译 | **成功** | 生成 `langraph` 可执行文件 |
| 解析自带 `trace.dat` | **成功** | 正常输出 `sched_waking` / `sched_switch` / 栈事件 |

## 结论

- **采集侧（perf / ftrace）：不可用。** 连不依赖 PMU 的软件事件都被拒，说明是容器策略在 `perf_event_open` 层面统一拦截，不是 `perf_event_paranoid` 调小就能解决的；tracefs 也无法挂载，ftrace 路径同样走不通。
- **分析侧（离线解析）：完全可用。** LanGraph 依赖的是 `libtraceevent` / `libtracefs` / `libtracecmd` 用户态解析库，读取已有的 `trace.dat`，不触碰内核采样接口。仓库自带的 11 MB 样例已跑通。
- **补充**：LanGraph 主流程本来就不用 perf。`script/get_ftrace.sh` 默认 `useperf=0`，只有 `-p 1` 才会额外跑 `perf record -a -g`；脚本里的 `clock="perf"` 指 ftrace 的 trace_clock 时钟源，不是 perf 工具。

## 建议工作流

在能访问 tracefs 的真机（你的 WSL2 / arm64 目标板）上采集，把 `trace.dat` 或 `ftrace*.log` 传到云空间做分析和出图；`trace.dat` 是架构无关的数据格式，x86_64 上可以解析 arm64 采到的数据。

```bash
# 真机（root，需 tracefs 可用）
sudo trace-cmd record -e sched -e irq -C perf sleep 60      # 生成 trace.dat
# 或
sudo ./script/get_ftrace.sh -t 60 -e 'sched|irq' -o langraph  # 生成 ftrace*.log

# 云空间（离线分析）
./langraph trace.dat                       # 事件流解析
python3 script/ftrace_latency.py           # 延迟出图（读 langraph/ftrace*.log）
```

## 补充：用 QEMU Guest 绕开限制（已验证）

上面说的「采集不可用」只针对**宿主机**。起一个 QEMU 虚拟机后，Guest 有独立内核，自带 tracefs，采集侧就通了：

| 能力 | 宿主机 | QEMU Guest（TCG） |
|---|---|---|
| tracefs 挂载 / ftrace 采集 | 拒绝 | OK，采到 381 条 sched/irq 事件 |
| perf 软件事件 | `EPERM` | OK |
| perf 硬件 PMU `cycles` | `EPERM` | `ENOENT`（TCG 不虚拟 PMU） |
| `langraph` 执行 | 能跑 | 能跑 |

可复现环境见 [`../qemu-guest/`](../qemu-guest/)（启动/构建脚本 + 完整串口日志；内核与 initramfs 由脚本构建，不入库）。

**但要注意**：云沙箱无 `/dev/kvm`，只能 TCG 软件模拟，指令和时序都被模拟器扭曲，采到的延迟数据**只能验证功能链路，不能用于真实性能/锁竞争分析**。真实分析仍应在真机或你 WSL2 里带 KVM 的 QEMU 上做。
